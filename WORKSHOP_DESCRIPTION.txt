[h2]Standalone and compatibility[/h2]
No original Quartermaster dependency. Disable original Quartermaster (Mod ID Quartermaster), older B47 sorting versions and duplicate copies when testing. No category mod is required: vanilla categories work alone.

Optional Better Sorting (BetterSortCC) supplies native categories. Better Containers (EURY_CONTAINERS / REORDER_CONTAINERS) retains its inventory UI; B47 uses its exposed categories. Both may be enabled; effective categories follow native metadata/load order. Optional-mod runtime acceptance is pending. Multiplayer peers need matching versions/mods.

Better Containers categories save as explicit item choices. Reselect after category changes/new types. Other UI combinations are not certified.

[h2]Clean Building — experimental multiplayer[/h2]
Requires the matching B47ANCE'd Rooms development source, API 1 with cleaning capability 1, installed separately on server and clients. Rooms currently has no Workshop item; subscribing to Quartermaster alone does not enable Clean Building. [url=https://github.com/B47ANCE/B47ANCEDRooms/tree/d603cd53903e01b6c575f4e1efcfa6da555e4a70]Matching Rooms source[/url]

With Rooms available, right-click while inside a loaded native building and choose Clean Building. The server selects eligible supplies from carried inventory and configured physical storage, directs fetching and equipping, adds 10 mL bleach by default before filling the remaining 10 L bucket capacity with water, and uses native blood/grime cleaning actions. Supported prepared solution is reused; refills account for residual bleach. Eligible borrowed supplies are returned to their original storage when current permission and capacity allow. Cancel Cleaning stops the job; supplies can remain carried. The summary reports actual actions, skips and retained items.

Rooms owns cleaning permissions and server sandbox settings for enable, borrowing, return, bleach dose, building tile limit and logistics timing. Client commands submit intent; authenticated server ownership and guarded native reconstruction control mutation.

[b]Single-player Clean Building is disabled.[/b] This feature requires finite pure-water sources; plumbed/infinite, tainted or mixed sources and protected/unsupported equipment are rejected. Native floor removal can affect neighboring squares across levels. The guard requires the entire possible footprint to be loaded, permitted and within the selected native building; many or all targets can be skipped. Ashes, graffiti and arbitrary dirt are not supported. Jobs do not resume after reconnect/restart. Native packet processing may interrupt an earlier action before Lua confirmation; the guard does not fix this engine limitation. No native/dedicated correctness claim is made.

[h2]Rooms and area sorting[/h2]
Optional Rooms supplies independent designation, native-room overrides, delegated ownership, per-action policies and boundary approval. Use Designate Room when installed. Without Rooms, native room/building sorting scopes and vanilla safehouse rules remain available; sorting has no hard Rooms dependency.

Inventory Sort offers the entire building, current room or current inventory/container. Both area choices include full carried inventory and bags, followed by configured physical storage. Restricted storage is filtered; withdrawal, deposit and configuration are independently checked on authority. Parent/admin metadata control does not grant gameplay access. Room policies do not lock unrelated vanilla transfers, entry or doors, or revoke a native transfer after dispatch. Legacy room records are imported by Rooms without deleting Quartermaster recovery data.

[h2]Sorting and window controls[/h2]
• Native category → item hierarchy with icons and full, partial and unselected states. Optional Group Items by Mod adds mod headings.
• Category/item search, Only Checked, Only Contents, presets and priorities; visible-row ranges, bulk selection and mouse/controller controls.
• Multi-container configuration, world sprite rail and verified Whole Container groups with inheritance and explicit customization/reset.
• Building/Room/Proximity choices. New sandbox configurations enable Whole Building discovery; existing explicit settings remain unchanged. Server settings control discovery range and visit optimization.
• Bounded movement queries reduce gaps between batches while preserving native per-item timing, permissions and server-observed arrival/completion. A failed batch without completed transfers stops safely; summaries distinguish planning skips from transfer failures.
• Native getter checks avoid category lookup errors. Floor/aggregate sources use native pickup; native acceptance pending.
• Native categories replace the retired B47 taxonomy. Server cleanup removes obsolete owned formats/category rules, retaining native rules, item choices, priorities and owned presets. Removed rules do not return on downgrade; back up saves.
• Open Quartermaster Menu is available in player inventory controls, including empty inventory and carried bags.
• Native resizing, adjustable container divider, controller layout actions and saved local geometry. Window Appearance controls background opacity from 20–100% (default 82%) with explicit reset.
• Tooltips, Help and controller inspection; native visual/scaling and cross-floor routing acceptance pending.

Click a category checkbox to select/clear or its label to expand/collapse. Full categories use native rules; partial selections use item names. Identical names share selections; presets are additive. Vanilla/installed UI mods retain native inventory presentation.

[h2]Supply planning[/h2]
• Dibs! item labels and Wanted/Needed lists with target quantities, qualifying carried counts and missing-demand Shopping.
• Add Remaining, bulk Add Items and Collect Remaining reuse authoritative Shopping; overlapping linked targets use the greater demand.
• Personal Shopping Preferences support condition, food state and remaining-use filters with item overrides.
• Source labels, duplicate confirmation and explicit Add Again preserve intent; replay/double-fire protection remains active.
• Manual Shopping and native crafting/building requirements, optional Project Cook CraftRecipe/supported EvolvedRecipe portions, and optional Neat Crafting/Neat Building controls.

Project Cook is optional. Cooking planning supports fresh-food full portions only. Partial modes, fluid demands, non-Food seasonings, prefilled bases and conflicting whole-item/portion demands are unsupported. Planning does not automatically craft, build or cook.
